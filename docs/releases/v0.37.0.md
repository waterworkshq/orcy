# v0.37.0 — Deepen: Installation Transaction

Architecture-deepening release that converts `@orcy/installer` from a descriptive append-only log into a transactional system with crash recovery. Introduces a two-file journal+manifest model with atomic writes and dedup, makes `update` replay the full install intent, splits `doctor` (liveness) from a new `verify` (consistency audit), hardens legacy migration and reconciles v1 manifests to v2, and adds G2 full recovery (viability-gated resume, active step-rollback, `--recover`). A three-agent independent cold review's findings were all remediated before release. Architecture review candidate 10 from the 2026-07-11 review; installer-only — no server, database, UI, MCP, or daemon changes. The macOS `launchctl` service-liveness detection and parent-directory fsync behavior are exercised only on Linux CI and warrant a real-platform validation pass as a follow-up (non-blocking; a false-negative there is safe, the prior false-positive is fixed).

## Two-file transaction model

A transient journal (`~/.orcy/install-journal.json`; its presence on disk signals an interrupted install) plus a committed manifest (`install-manifest.json`) replace the single append-only log. Both files are written atomically via a shared `atomicWriteJson` helper — temp file in the target directory, `fsync` of the data (and best-effort parent-directory `fsync`), atomic rename, temp cleanup on failure. `record()` is a journal-aware seam: during an install it redirects to the journal; otherwise it writes the manifest with `{path, action}` dedup and metadata upsert (hash/keys/backup/marker), so a re-install no longer grows a duplicate-laden manifest and a refreshed hash survives instead of being dropped.

## Update replays full intent

`updateInstall` now re-applies env, service, MCP config, markdown, and skills from a typed `InstallIntent` persisted in the manifest — instead of only re-running packages plus fenced-markdown injection. The old `AGENTS`/`CLAUDE` substring heuristic is gone. Markdown injection is remove-then-inject: a shared `stripFence` clears every complete marker pair (and any orphan/partial markers) before re-injecting, so `update` is idempotent across duplicate or malformed fence states. Skill replay hash-compares before overwriting so a user-edited skill dir is preserved (G6), and env replay updates managed endpoint fields (PORT/HOST/ORCY_API_URL) while preserving secrets.

## doctor / verify split

`doctor` stays a scannable, cron-safe liveness probe and gains two read-only checks (a stale-journal WARN and service status via the existing `serviceStatus` probe). A new `verify` command is a read-only consistency auditor: it cross-references the manifest against disk and reports drift (missing recorded paths, duplicate entries, a stale journal), with footprint dirs (`src`/`cache`/`node_modules`) reported informationally rather than as drift — a healthy install has them. Neither command mutates the filesystem.

## Migrate hardening + v1→v2 reconcile

The legacy `~/.kanban → ~/.orcy` migration rewrites manifest paths immediately after the irreversible rename (so post-migrate uninstall finds the files) and is best-effort from there: a single step failure no longer aborts the whole migration. A new `reconcile` step upgrades a v1 (or versionless) manifest to v2 on `update` — deduping entries, rewriting stale `~/.kanban` paths (separator-aware, so a sibling like `~/.kanban-notes` is untouched), and bumping the version — so existing installs upgrade in place.

## G2 full recovery

A stale journal triggers viability-aware recovery. **Resume** discards the journal and re-runs the wizard; G8 idempotency makes already-done steps converge rather than duplicate. **Rollback** actively reverses the journal's done steps via a shared `reverseEntry` (the same switch `uninstallAll` uses), including stopping a service the partial install started; an incomplete rollback preserves the journal and aborts rather than installing over a half-cleaned state. A `--recover` flag enables CI auto-recovery (resume-if-viable, else rollback). An unresolved `registerAgent` — a POST that succeeded but whose local credential write did not — blocks resume (which would POST a second agent) and surfaces the orphaned agent id; the both-files post-commit window (commit's write finished, journal unlink interrupted) is finalized silently instead of offered for rollback.

## CLI hardened

Unknown arguments now error instead of silently installing: `--yes --bogus` or `--recover updtae` exit with usage rather than triggering a full non-interactive install. `--yes`/`-y`/`--recover` are recognized flags, the stale-journal hard-fail propagates a non-zero exit code (CI signal preserved), and a `@clack` cancel is treated as abort rather than falling through to resume.

## Cold review + remediation

A three-agent independent cold review (codex/GPT-5.6, non-overlapping file ownership) produced ~30 findings across four severity tiers; all four were remediated before release — recovery-contract soundness (registerAgent orphaning, resume idempotency, rollback completeness), data-loss and correctness paths (missing-hash skill deletion, manifest-deleted-on-failure, path over-match, markdown multi-fence, sentinel order), atomic-write durability (per-write unique temp, `fchmod` mode guarantee, fd cleanup, real `fsync` error propagation), and CLI/UX accuracy (exit code, validate-all-args, select cancel, verify/doctor output, backup-prune glob). Each fix has a dedicated test where testable.

## Verification

- `@orcy/installer`: 129 tests pass (hermetic — real `node:fs` against a temp home; `node:child_process`/`fetch`/`@clack` mocked). Zero `packages/installer/` typecheck errors.
- No `@orcy/api`, `@orcy/ui`, `@orcy/mcp`, `@orcy/daemon`, or `@orcy/shared` changes — those packages are untouched.

## No operator action required

No schema changes, no migrations, no ADRs, no breaking changes. Existing installs pick up reconcile on their next `orcy-install update`. The `--recover` flag is opt-in; without it, non-interactive runs still fail safely on a stale journal (unchanged).
