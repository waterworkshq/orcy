# v0.37.0 — Deepen: Installation Transaction

v0.37.0 is an architecture-deepening release that converts `@orcy/installer` from a descriptive append-only log into a transactional system with crash recovery. A transient journal plus a committed manifest replace the single read-modify-write file; both are written atomically (temp + fsync + rename) with `{path, action}` dedup and metadata upsert; `updateInstall` replays the full install intent (env, service, MCP, markdown, skills) from a typed `InstallIntent` persisted in the manifest; a new `verify` command audits manifest↔disk consistency alongside a cron-safe `doctor`; legacy migration is hardened and v1 manifests are reconciled to v2; and crash recovery adds viability-gated resume, active step-rollback, and a `--recover` CI flag. Architecture review candidate 10 from the 2026-07-11 review; installer-only.

Before v0.37.0, the installer recorded what it did but owned no notion of intended state, transaction boundary, or recovery. Manifest writes were plain read-modify-write (no temp+rename, no fsync), `record()` appended a fresh entry on every re-install so the manifest grew duplicate-laden, and an interrupted install left no recoverable signal — the manifest was the only file and it was written throughout. `updateInstall` only re-ran packages plus fenced-markdown injection whose path matched an `AGENTS`/`CLAUDE` substring heuristic, leaving MCP config, skills, the service unit, and env stale across an upgrade. Uninstall removed files under a still-running service (macOS launchd respawned via `KeepAlive`), deleted the manifest on partial failure (losing retry state), and could recursively delete a user-modified skill. The macOS service-install path was unreachable; migrate was irreversible after the `~/.kanban → ~/.orcy` rename and left manifest paths pointing at the old home; and the package had zero tests.

---

### The Two-File Transaction Model

A transient journal (`~/.orcy/install-journal.json`; its presence on disk signals an interrupted install) plus a committed manifest (`install-manifest.json`) replace the single append-only log. During an install, `record()` redirects to the journal; the manifest is written exactly once, at `commitJournal`, from the journal's `done` entries. Both files are written through a shared `atomicWriteJson` helper — temp file in the target directory, `fsync` of the data, atomic rename, temp cleanup on failure — so the manifest path never holds a partial write. `record()` dedups on `{path, action}` and upserts optional metadata (hash/keys/backup/marker), so a re-install no longer grows a duplicate-laden manifest and a refreshed hash survives instead of being dropped. `commitJournal` preserves an existing reconciled version (it does not hardcode `1` and downgrade a v2 manifest).

### Idempotent Update Replay

`updateInstall` reads the persisted `InstallIntent` and re-applies env, service, MCP config, markdown, and skills — the `AGENTS`/`CLAUDE` substring heuristic is gone. Markdown injection is remove-then-inject: a shared `stripFence` clears every complete marker pair (looping, so duplicate pairs from a prior bug are all cleared) plus any orphan/partial markers before re-injecting, so `update` is idempotent across duplicate or malformed fence states. Skill replay hash-compares before overwriting (a user-edited skill dir is preserved), and env replay updates managed endpoint fields (`PORT`/`HOST`/`ORCY_API_URL`) while preserving secrets. Old manifests without a recorded intent fall back to packages + markdown with a notice.

### `doctor` / `verify` Split

`doctor` stays a scannable, cron-safe liveness probe and gains two read-only checks (a stale-journal WARN and service status via the existing `serviceStatus`). Its FAIL lines now match the summary (`PATH` is a hard fail; `.env`/credentials/manifest are soft WARN). A new `verify` command is a read-only consistency auditor: it cross-references the manifest against disk and reports drift (missing recorded paths, duplicate entries, a stale journal), with footprint dirs (`src`/`cache`/`node_modules`) reported informationally rather than as drift — a healthy install has them. Neither command mutates the filesystem; `verify` checks a stale journal before its no-manifest early-return so an interrupted first install is reported.

### Migrate Hardening + v1→v2 Reconcile

The legacy `~/.kanban → ~/.orcy` migration rewrites manifest paths immediately after the irreversible rename (separator-aware, so a sibling like `~/.kanban-notes` is untouched) and is best-effort from there — a single step failure no longer aborts the whole migration. A new `reconcile` step upgrades a v1 (or versionless) manifest to v2 on `update` — deduping entries, rewriting stale `~/.kanban` paths, and bumping the version — so existing installs upgrade in place. The both-files post-commit window (commit's write finished, journal unlink interrupted) is detected and finalized silently rather than offered for rollback.

### Crash Recovery

A stale journal triggers viability-aware recovery. **Resume** discards the journal and re-runs the wizard; because each install step is now idempotent, the already-done ones converge rather than duplicate. **Rollback** actively reverses the journal's done steps via a shared `reverseEntry` (the same switch `uninstallAll` uses), including stopping a service the partial install started; an incomplete rollback preserves the journal and aborts rather than installing over a half-cleaned state. A `--recover` flag enables CI auto-recovery (resume-if-viable, else rollback); without it, non-interactive runs still fail safely. An unresolved `registerAgent` — a POST that succeeded but whose local credential write did not — blocks resume (which would POST a second agent, orphaning the first) and surfaces the orphaned agent id; `registerAgent` marks the step failed and rethrows rather than swallowing the post-POST persistence error.

### CLI Hardened

Unknown arguments now error instead of silently installing: `--yes --bogus` or `--recover updtae` exit with usage rather than triggering a full non-interactive install (only `argv[0]` was validated before). `--yes`/`-y`/`--recover` are recognized flags, the stale-journal hard-fail propagates a non-zero exit code (CI signal preserved), and a `@clack` cancel is treated as abort rather than falling through to resume.

### Cold Review + Remediation

A three-agent independent cold review (codex/GPT-5.6, non-overlapping file ownership over the transaction core, the reversal hub, and the entry points) produced ~30 findings across four severity tiers; all four were remediated before release — recovery-contract soundness (registerAgent orphaning, resume idempotency, rollback completeness), data-loss and correctness paths (missing-hash skill deletion, manifest-deleted-on-failure, path over-match, markdown multi-fence, sentinel order), atomic-write durability (per-write unique temp, `fchmod` mode guarantee, fd cleanup, real `fsync` error propagation), and CLI/UX accuracy (exit code, validate-all-args, select cancel, verify/doctor output, backup-prune glob). Each fix has a dedicated test where testable.

### What Stayed the Same

No `@orcy/api`, `@orcy/ui`, `@orcy/mcp`, `@orcy/daemon`, or `@orcy/shared` changes — the server, database, UI, MCP surface, daemon, and CLI dispatch tools are untouched. No new REST routes, MCP tools, or SSE event types. The install wizard's interactive flow is unchanged.

### Operator Action Required

**None.** No schema changes, no migrations, no ADRs, no breaking changes. Existing installs pick up reconcile on their next `orcy-install update`. The `--recover` flag is opt-in; without it, non-interactive runs still fail safely on a stale journal (unchanged). The macOS `launchctl` service-liveness detection and parent-directory fsync behavior are exercised only on Linux CI and warrant a real-platform validation pass as a follow-up (non-blocking — a false-negative on macOS `doctor` service-status is safe; the prior false-positive is fixed).

### Verification

- `@orcy/installer`: 129 tests pass (hermetic — real `node:fs` against a temp home; `node:child_process`/`fetch`/`@clack` mocked). The package went from zero tests to 129 across the release.
- `@orcy/installer` typecheck: zero `packages/installer/` errors.
- Three-agent cold review (~30 findings) — all four tiers remediated before release.
