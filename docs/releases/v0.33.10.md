# v0.33.10 — Deepen: Workflow Gate Advancement

> Architecture-deepening release. ADR-0042 documents the fail-closed atomicity contract.

## What changed

Concentrates the Workflow Gate advancement transaction into one deep module (`advanceGates`) behind a single entry point. Per-gate `db.transaction` owns guarded CAS satisfaction, tx-aware audit INSERT, and recovery handoff for eligible `on_fail` gates. Five satisfaction paths (lifecycle, pulse, automation, manual unblock, redemption) route through the one entry; a sixth (template pre-satisfied-at-attach) is a creation-time exception.

## Why it matters

**The advancement transaction is now atomic and fail-closed.** Before this release, gate satisfaction and its audit emission were separate auto-commit writes — a crash between them left a satisfied gate with no provenance record, and a swallowed audit error hid code bugs as silently-satisfied-no-audit gates. Now, an audit or handoff INSERT failure rolls back the satisfaction entirely. The gate stays unsatisfied until operator intervention or a genuinely new matching trigger. This surfaces problems as investigable non-advancing gates rather than hiding them.

**A reachable production bug is closed.** The old `createRecoveryTask` path collapsed every non-successful recovery-publication outcome (vetoed, rejected, guard mismatch) to `return null`, which caused `spawnRecoveryForGate` to skip silently. A governance-vetoed Recovery publication could strand a satisfied `on_fail` gate with `recoveryTaskId = null` forever — reachable on production, without a process kill. A new boot-only `RecoveryCoordinator` replaces the old live-config spawn path and eliminates the null-collapse by construction.

**Six-way provenance normalization.** The `satisfiedByEventId` column is now populated for all six satisfaction paths (was: four of six rendered *nothing* in the UI). Lifecycle gets the real Task Event id (via a new `transition-emitter.ts` seam change); manual unblock gets a self-referential audit id; redemption gets the recovery context id.

**Manual unblock absorbed into the single authority.** The fifth mutation path (`manualUnblockGate`) now routes through the same `advanceGates` module. The distinct `workflow_gate_unblocked` audit action is preserved, along with the CR-13/TG-1 carveout (repeat unblock attempt emits an audit even on `already_satisfied`).

**Redemption audit gap closed.** `redeemOneContext` now emits a per-gate `workflow_gate_satisfied` audit (was: zero audit events — only a notification with a count). The `workflow.recovery_succeeded` notification stays as the UX surface; the audit is the provenance record. Two records, two roles.

## Key decisions (ADR-0042)

- **Fail-closed, not eventual delivery.** Source hooks are one-shot — there is no outbox, no advancement-attempt ledger, no automatic replay. The ADR states this explicitly and does not claim eventual liveness.
- **Per-gate transaction, not batch.** One gate's audit or handoff failure does not block later independent gates.
- **Boot-only Recovery Coordinator, no periodic timer.** The durable handoff earns its keep on the reachable null-collapse bug; the crash-window coverage is a bonus. Skeptical's YAGNI risk-acceptance is documented.
- **Fork A: caller-supplied preallocated audit IDs.** sql.js `.run()` returns boolean `true`, not `{changes:N}` or `lastInsertRowid` — empirically verified. Driver-agnostic.
- **Fork B: immutable frozen handler config.** A restart must honor the policy in force at advancement time, not silently adopt changed operator configuration.

## Schema changes

- **New table:** `task_recovery_handoffs` (migration `0060`). Status enum: `expected | consumed | blocked` (no `spawned` state). The coordinator consumes handoff rows joined to `task_creation_attempts`.

## Operator action required

**None.** No schema migration action needed beyond the standard migration runner. No configuration changes. No breaking changes to REST/MCP/SSE contracts. The `transition-emitter.ts` seam change is additive (optional `eventId?` on `TransitionHook` — existing consumers ignore it by default).
