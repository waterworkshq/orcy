# v0.48.0 — Hardening: Schema Truth, Account-Switch Integrity, Type Domains, Platform Policy

v0.48.0 lands a documentation-truth and enforcement batch: the physical SQLite schema now enforces the enum domains the documentation always claimed (`agents.type` and six more columns gain real CHECK constraints), the schema and security documents are reconciled column-by-column with what actually exists, and the agent/CLI type domain is derived from one constant end to end — TypeScript union, Drizzle columns, wire validation, and database CHECK all reference `AGENT_TYPES`. Account switches no longer fire an aborted detail refetch against the retired account's API, new users default to the editor role instead of admin, transition-budget escalations deduplicate against prior ceilings and disclose their refusal reason to remote owners, and the repository states and verifies a supported-Node policy (24 LTS and 26 Current) with a CI matrix that proves the native `better-sqlite3` binding builds and loads on every supported major. Dependency updates are now automated: grouped weekly Dependabot bumps with majors riding the normal review gates, and this release ships the first two automated refreshes — a 39-package minor/patch group and nodemailer 8→10.

Before v0.48.0, `docs/DATABASE.md` claimed `CHECK (IN …)` constraints on 74 column rows that the physical schema never created, described columns that no longer exist, and missed domain drift — while the API documentation simultaneously said the opposite ("no SQL CHECK") on other rows. Enum domains lived only in application code: the daemon engine fed `agents.type` through an `as any` cast, an out-of-domain CLI type surfaced as a runtime insert failure instead of a typecheck error, and the daemon registration wire accepted arbitrary `cli_type` strings. Switching accounts could — in a narrow render race — kick off one aborted `GET /tasks/:id/details` against the retired account's endpoint while the old query cache was being torn down. New users were created as `admin` by default. Transition-budget escalations re-fired on every breach at any ceiling, and remote owners received a bare 409 with no reason. Nothing told local tooling which Node major to use, so a machine defaulted to another major hit a misleading native-binding failure, and dependency bumps were entirely manual.

---

### Transition-Budget Escalation and Refusal Disclosure

Budget-refusal escalation is now ceiling-aware: the first refused guarded transition at a ceiling strictly above every prior breached ceiling emits one escalation event and best-effort notification to the habitat's humans, while same-ceiling or lower-ceiling repeats stay silent — raising the ceiling later makes refused candidates eligible again without a duplicate storm. The known `transition-budget` audit actor is mapped with `system` provenance, preserving raw stored event data. Separately, remote submit and release refusals now disclose their cause: the typed `TASK_SUBMIT_FAILED` / `TASK_RELEASE_FAILED` 409 envelopes carry `details.reason: "transition_budget_exhausted"` — no counts or ceilings leak — and remote submit revalidates ownership and status inside the transaction before the budget guard, so a raced reassignment or wrong-state refusal cannot be masked by the budget answer. Human actors remain unmetered.

### Default Role: Editor

New users are created as `editor`, not `admin`. The repository's omitted-role fallback changed with it; initial-admin registration still explicitly grants `admin`, and existing rows are untouched — migration `0089` swaps only the column default. The API documentation's role-enum enforcement notes and the DATABASE.md row were corrected to match (the previously documented `users.role` CHECK constraint never existed).

### Schema Documentation Reconciliation and Physical Enum Enforcement

Two documentation passes brought `docs/DATABASE.md` to ground truth: the 74 fictional `CHECK (IN …)` claims are gone (the physical schema had none), nonexistent columns deleted, stale domains synchronized — and a separate section-by-column reconciliation against the live Drizzle schema fixed drifted sections, nullable-without-default markings, and the `signal_type` domain. `docs/SECURITY.md`'s Task-object row now states the write-time Workflow/gate fences exactly: the admin attach validates node ancestry up front (`400 Invalid workflow nodes` before the first write), while the template-aggregate publisher, legacy `applyTemplate` boundary, and Workflow-Recovery participant refuse at statement time inside their transaction with the whole aggregate rolled back — no cross-Mission or cross-Habitat endpoint can persist a Workflow/gate row.

Migration `0090` then makes the strongest of those claims physically true: seven documented enum domains — `agents.type`, `task_events.signal_type`, `task_events.verification_state`, `cicd_runs.verification_state`, `cicd_runs.status`, `tasks.priority`, `workflows.status` — gain real CHECK constraints, applied through guarded per-column swaps so a pre-existing out-of-domain value defers enforcement with a stable code and report instead of bricking startup. `task_events` (zero inbound foreign keys) is rebuilt through the archive-then-mirror pattern with a `task_events_orphans_0090` archive for rows that would fail the mirror; `agents.type` is re-added nullable with `CHECK (type IS NOT NULL AND type IN (…))` because a bare `IN` passes NULL, and the migration force-resets `PRAGMA ignore_check_constraints` off on exit. The staged-migration runner itself was hardened first: a ROLLBACK guard on recording failures, token-matched named-check detection, and a generalized enforcement-stage list.

### Account-Switch Retirement Integrity

Retiring the previous account's query client no longer clears its cache synchronously mid-teardown. `SessionStateProvider.replace` keeps cancellation, token swap, store resets, and modal close synchronous, pushes the retired client onto a generation-tagged list, and clears it in a StrictMode-safe effect keyed on the session generation — after the old tree has unmounted, with still-mounted newer clients provably never cleared. The race — a still-mounted observer's own refetch effect firing one aborted `GET /tasks/:id/details` at the retired account's endpoint after the synchronous clear — is gone: the journey test asserts zero post-retirement task requests across repeated serial runs (previously reproduced at a 5-in-25 rate), and retirement teardown is deterministic under test.

### One Agent-Type Domain

`AGENT_TYPES` in `@orcy/shared` is now the single source of the agent/CLI type domain. The `AgentType` union derives from the constant, the Drizzle column enums are generated from it, the daemon registration Zod schema constrains `detectedClis[].type` with `z.enum(AGENT_TYPES)`, and the physical CHECK domain from migration `0090` is parity-tested against it at compile time and at runtime — the `as any` casts on the daemon feed are gone. Unvalidated rows get defense in depth: legacy or directly-written `daemon_agents.cli_type` values outside the domain are skipped with a warning at the repository read boundary and rejected on the daemon claim path before any task is claimed, so a foreign type can neither pollute the poll loop nor churn claim-and-fail cycles.

### Node Support Policy and CI Matrix

The supported Node.js versions are now stated and enforced: latest LTS (today 24) and latest Current (today 26), expressed in `engines.node` as disjoint major ranges (`>=24.0.0 <25.0.0 || >=26.0.0 <27.0.0` — 25 was never supported), pinned for local tooling via `.node-version` and `.nvmrc`, and documented in CONTRIBUTING with an explicit roll-forward policy (a new major enters at stable Current; a major leaves when its LTS successor is promoted and green). CI runs the lint/test workflow and the production-migration gate as a matrix over both majors, each proving `better-sqlite3` builds and answers a real in-memory query; the fallback corepack bootstrap is version-pinned so the trust root for the pinned pnpm stays deterministic.

### Dependency Automation and Refresh

Dependabot now runs weekly with grouped minor/patch bumps (one reviewable PR), ungrouped majors riding the normal review gates, a five-PR open limit, and `chore(deps)` commits excluded from the changelog. The first automated refreshes ship in this release: a 39-package minor/patch group (fastify stack, drizzle, tiptap, react, recharts, vite, playwright, oxlint and friends) with the compatibility fixes it required — recharts tooltip label coercion, the MCP wire test build made once-per-run and watch-aware (rebuild on production edits only, torn dist never served, Windows path normalization), and the cold-migration test database pinning `foreign_keys` off after build — plus nodemailer 8→10 (v10 ships its own TypeScript types; the transport is non-pooled and unaffected by the pooled-idle changes; the security-hardened address parser comes along). The `.gitignore` blanket dot-directory rule no longer hides new `.github/` files, and a regression check pins their visibility.

### What Stayed the Same

Agent admission policy, personal-habitat openness, the plugin system, daemon, CLI, and MCP surface. No new REST routes, MCP tools, or notification events — the budget refusal reason is an additive field inside the existing typed 409 envelope. `0000_schema.sql` is untouched; both migrations are additive over the journal. The Task metadata editing, work-source admission, and completion-timing contracts from v0.47.0 are unchanged (the modal's fade-in now triggers once per presentation and the edit retry gate closes at save start).

### Schema Changes

- **`0089_user_role_default_editor.sql`** — `users.role` column default swaps `admin` → `editor`; existing rows untouched.
- **`0090_documented_enum_check_constraints.sql`** — seven CHECK constraints over documented enum domains (`agents.type`, `task_events.signal_type`, `task_events.verification_state`, `cicd_runs.verification_state`, `cicd_runs.status`, `tasks.priority`, `workflows.status`); `task_events` rebuilt via archive-then-mirror with the `task_events_orphans_0090` archive.

### Operator Action Required

**None for a clean upgrade.** Both migrations run automatically on startup. If `task_events_orphans_0090` is non-empty after the upgrade, those archived rows reference tasks that no longer exist — review and delete them deliberately; the API no longer surfaces them. Supported Node majors are 24 and 26; a deployment on Node 25 was never supported and `engines.node` now says so.

### Verification

- Every merge's main-push CI green; the matrix covers Node 24 and Node 26 on the lint/test workflow and the production-migration gate, each leg proving the native `better-sqlite3` build and an in-memory query.
- Schema enforcement: pre-existing out-of-domain values defer with a stable report (verified against seeded legacy databases); orphaned task events archive rather than abort; the parity suite pins the TS union, Drizzle enums, and physical CHECK domain to one constant at compile time and runtime.
- Retirement: zero post-retirement task requests asserted across 12 serial full-journey runs (pre-fix reproduction: 5/25 runs with one aborted details GET); UI trio 81/81, session continuations 98/98, StrictMode rehearsal and mounted-newer-client race both pinned by dedicated tests.
- Agent-type domain: 108/108 across the touched API suites; register-wire rejection of foreign CLI types, claim-path rejection, and read-boundary skip each pinned by their own test; typecheck and lint clean workspace-wide.
