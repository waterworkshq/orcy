# v0.41.0 — Deepen: Authoritative HTTP Route Assembly

v0.41.0 gives Orcy's production HTTP application one authoritative assembly: a single staged module constructs Fastify, registers every route surface (both local API prefix groups, realtime SSE, the Remote Participant API, the optional UI, and System Plugin routes), and hands the executable only a narrow runtime handle — listen, close, log, and a one-shot plugin-route install. Authentication is now policy-installed: every route declares its effective credential policy through typed route config, and the declaration itself installs the core-owned guard before route-level authorization runs; a route without a declared policy fails boot instead of silently serving. ADR-0049 records the assembly and policy contract; ADR-0050 records the declared plugin HTTP seam that supersedes the old raw-callback contract (ADR-0041).

Before v0.41.0, route registration was split between the production entrypoint and a separate test-maintained copy of the route list, so tests could pass while production served routes the inventory never saw. Authentication was inferred from middleware function names and public-route regexes — descriptive labels that could drift from the guards actually installed — and an old exception even misclassified the plugin listing endpoint as public. Plugin HTTP extensibility exposed the raw Fastify registration callback, running plugin code at mount time with no core-owned authentication. Two pre-existing security defects shipped in that gap: the Presence endpoints accepted anonymous, caller-forged identities, and an unverified provider-invite acceptance route could provision remote pods from a bare invite UUID. Unmatched CI webhooks failed open under remote posture with zero secrets configured, Slack slash commands 500ed on their real form-encoded wire format, and the `X-API-Version`/`Deprecation` headers were stamped at a lifecycle stage that never reached the wire.

---

### One Authoritative Assembly

`createHttpApplication` is now the only place that constructs Fastify and registers production routes. Assembly is staged and one-way: core surfaces register first (resolving in a `core_registered` state), validated plugin routes install exactly once, and `finalize()` takes a route inventory snapshot, runs the readiness gate, and completes Fastify boot — failing before listen if any route lacks a declared policy. Production boot holds a narrow handle, not the Fastify instance. A source-boundary guard test backs the capability boundary: only the assembly may import `fastify` as a value or acquire Node's CommonJS loader capability (`createRequire`) from a literal `node:module`/`module` import, so out-of-assembly route registration is a review failure by construction. Non-literal/interpolated specifiers are the guard's documented scan residual.

### Policy-Installed Authentication

The closed ten-policy catalog — `anonymous`, `human`, `agent`, `local_actor`, `registration`, `daemon`, `realtime`, `remote_participant`, `manual_invite`, and `verified_ingress` — is declared per route through typed config, and the declaration installs the matching core-owned guard. Readiness is closed: a missing, unknown, or conflicting declaration prevents the application from becoming ready, including generated HEAD twins and deprecated-prefix mirrors. `anonymous` is an explicit policy rather than an inference. Provider-signed webhooks moved behind closed core verifiers that also drive exact raw-body capture (each verifier's declaration owns raw-body eligibility), and a verifier that is structurally inert — present in the registry but unable to actually verify — now fails readiness instead of silently passing traffic. Object-level authorization (habitat, team, grant, admin, ownership checks) is unchanged and still layered after authentication.

### Security Containments

Presence endpoints are human-authenticated and identity-bound: join, heartbeat, leave, and viewer reads require the JWT, identity is derived server-side from the authenticated user, and the client can no longer supply or forge identity fields; sessions that end abruptly expire through the existing two-minute TTL. The unverified provider-invite acceptance route (`POST /shared/invites/accept-provider`), which provisioned remote participants from a bare invite UUID plus caller-authored identity, is removed pending a properly state-consuming callback design. Unmatched GitHub and GitLab CI webhooks now fail closed under remote posture — with zero secrets configured they no longer dispatch — while zero-secret local development keeps its fail-open posture.

### Declared Plugin HTTP Routes

Plugins no longer hand Orcy a raw Fastify registration callback. Routes are declared in the manifest (`customHttpRoute` with `routeId`, method, and relative path) and implemented by keyed handlers (`httpHandlers`), and core mounts them under `/api/v1/plugins/:pluginId/*` with a deprecated `/api/plugins/:pluginId/*` mirror. Authentication is fixed to local actor (human-or-agent) — plugins cannot select or weaken it — and a handler failure fails only its own request through the global error envelope with plugin/route-tagged logging; no quarantine, retries, or mount-time plugin execution. **Breaking (prerelease plugin SDK):** a plugin still exporting the old `routeHandlers` callback is rejected at load with an explicit migration error naming the replacement.

### Ingress Repairs

GitHub issues webhooks dispatch to every integration connection whose own secret verifies — previously only the first matching connection received the event while GitHub still saw 200, so omitted habitats could not recover through redelivery; a per-connection failure is contained and later matches still run. Slack slash commands complete on their real `application/x-www-form-urlencoded` wire format: a route-scoped parser (platform URLSearchParams decoding, duplicate keys last-wins, null-prototype string fields) feeds the command handler under both prefixes, while exact-byte signature verification — taken from the raw-body capture before parsing — is unchanged, and no other route's content-type handling changed.

### Operator-Visible Headers

`X-API-Version` is now wire-visible on every response, and deprecated `/api` responses carry `Deprecation: true`. Both headers were previously stamped in an `onResponse` hook — after Fastify had already sent the response — so neither ever reached clients; both now apply at an `onSend` stage that actually delivers. Current/deprecated prefix parity is exact and continuously pinned by a behavior-derived route baseline.

### What Stayed the Same

Endpoint behavior, handlers, object-level authorization, workers, schedulers, daemon, CLI, MCP surface, and the database schema are unchanged. The deprecated `/api` prefix is retained, paired 1:1 with `/api/v1`. The Remote Participant API remains independently mounted under `/api/shared` behind its own credential. Discord and GitLab verifier postures, registration's local-dev open posture, and realtime/SSE semantics are pinned unchanged by the characterization suite.

### Operator Action Required

**Plugin authors must migrate before upgrade.** Any plugin exporting the legacy `routeHandlers` Fastify callback will be rejected at load. Move each route into a `customHttpRoute` manifest contribution (`routeId`, method, relative path) and export its handler under `httpHandlers[routeId]`; the load error names this migration. No core action is required: no migrations, no configuration changes. Operators relying on anonymous Presence clients (none ship in this repository) must authenticate those callers; the browser client already sends its JWT.
