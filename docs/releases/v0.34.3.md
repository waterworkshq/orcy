# v0.34.3 — Refactor: task-dispatch field-descriptor declaration + firewall characterization

A gated refactor of the `orcy_habitat_task` action metadata, landed with the characterization tests that lock its agent-visible surface.

## Derive task-dispatch action metadata from one field-descriptor declaration

`orcy_habitat_task` action metadata — the action enum, shared wire-properties, the per-action required map, and the handler map — is now derived from a single `defineActions` declaration backed by a field-descriptor registry (`packages/mcp/src/tools/field-descriptor.ts`). Removes the parallel inventories (the standalone `actions[]` array, the `sharedParams` block, `TASK_REQUIRED_PARAMS`, and the mirrored test enum). A gated spike: the agent-visible MCP surface is byte-identical, locked by the new firewall characterization tests (which pass unchanged).

[`5eebb2c`](https://github.com/waterworkshq/orcy/commit/5eebb2cbd05c17b1bc64fb1c71bb724b75804d7d)

## Lock `orcy_habitat_task` agent-visible behavior (firewall characterization)

Adds snapshot/equality tests pinning the `orcy_habitat_task` tool's agent-visible behavior: the full `ListTools` descriptor (name, action enum + order, every shared param, `required: ["action"]`), `CallTool` results (unknown action, each missing sentinel `undefined`/`null`/`""`, multi-missing, thrown `Error`, non-`Error` throw), and audit attribution (`withAuditToolContext` receives the unchanged `(toolName, action)`). The safety net for the descriptor refactor — any future change requiring these snapshots to be edited has failed the gate.
