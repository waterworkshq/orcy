# v0.48.1 — UI dependency updates and more reliable verification

This maintenance release updates the web UI dependencies and makes the test suite faster and more reliable without dropping coverage. It adds no production database migrations or public API changes.

## Web UI dependency updates

React Router moves to v7, Zustand to v5, and `@dnd-kit/sortable` to v10. The router upgrade preserves atomic account-switch navigation, and the board’s column and task-card subscriptions use shallow comparison with Zustand v5. Drag-and-drop keeps a compatible `@dnd-kit/core` version. The UI test suite also moves to jest-dom v7 with its required DOM testing peer. [#197](https://github.com/waterworkshq/orcy/pull/197) · [#198](https://github.com/waterworkshq/orcy/pull/198) · [#199](https://github.com/waterworkshq/orcy/pull/199) · [#200](https://github.com/waterworkshq/orcy/pull/200)

## Faster CI without dropping tests

CI runs the default API suite in two parallel Node 24 shards, with four Vitest workers each. Root script tests, the other workspace suites, and the serial Learning Loop concurrency proof run in a separate job. Node 24 and 26 still verify native SQLite compatibility, and both run the separate production migration gate. The latest pre-release lint-and-tests run finished in about five and a half minutes; runner timings vary. [#215](https://github.com/waterworkshq/orcy/pull/215) · [#217](https://github.com/waterworkshq/orcy/pull/217)

## Test fixtures that better match production

The API suite reuses a migrated SQL.js schema image across eligible test files and prebundles Drizzle modules. Both the shared image and local fallback now replay the migration journal in order instead of scanning old SQL files. The fixture keeps the intentional FTS5 fallback and production-only enforcement exclusions, but fails on other migration errors rather than hiding them. Native migration tests still exercise real file-backed upgrades and restarts; reusable historical fixtures avoid repeating the same setup. [#211](https://github.com/waterworkshq/orcy/pull/211) · [#213](https://github.com/waterworkshq/orcy/pull/213) · [#216](https://github.com/waterworkshq/orcy/pull/216) · [#220](https://github.com/waterworkshq/orcy/pull/220)

## More reliable race and watch tests

The review-governance test advances its worker clock rather than waiting 30 seconds for a grant to expire, while still testing the same admitted HTTP request. The scheduled-retry test makes both real SQLite workers compete for the same retry slot after both have confirmed it is empty. Other cross-process tests use readiness signals or give workers more startup headroom. The MCP wire test watcher detects in-place edits and treats unreadable inputs as changed, with probes isolated from the live checkout.
