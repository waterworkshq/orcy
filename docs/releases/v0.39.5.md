# v0.39.5 — Patch: Record delivery attempts for plugin notification channels

Plugin notification channel dispatches (webhooks, HTTP targets, etc.) sent notifications without creating or updating delivery attempt records, leaving no auditable trail of attempts, outcomes, or errors — unlike the in-tree channels (email, SMS, in-app) which all record into `notification_delivery_attempts`.

## What changed

Plugin channel dispatches now create a delivery attempt record at the start of each send and update it with the final status, HTTP status code, error message, and timestamps upon completion. This brings plugin channels to parity with the in-tree notification delivery tracking, so operators can inspect failed deliveries, retry timing, and error details uniformly across all channel types.

## Verification

- `@orcy/api` tests: 20 passed in `notificationChannelDelivery.test.ts` (includes new delivery-attempt assertions).
- `@orcy/api` typecheck: clean.

## No operator action required

No schema changes, no migrations. The `notification_delivery_attempts` table already exists; plugin channels now write to it.
