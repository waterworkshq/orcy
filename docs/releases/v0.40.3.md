# v0.40.3 — Patch: Settings-shape hardening, MCP docs guard, release tooling

An adversarial audit of the codebase at v0.40.2 filed eight findings; this patch resolves the six that are fixes and guards with no behavior tightening. The remaining two — a watchdog for automation-action plugin invocations and consolidation of webhook URL validation onto the canonical SSRF checker — intentionally ship as their own follow-up patch so the only behavior-changing hardenings are isolated and easy to roll back.

## Settings blobs are complete on first write and on every read

The v0.40.2 fix ensured first-ever partial PATCHes persist complete objects for four settings blobs; two more had the same gap and are now covered. A partial `autoAssignSettings` PATCH on a habitat with no stored settings now backfills all six declared fields from the canonical defaults (the default factory existed but was never wired into the merge registry), and `codeReviewSettings` — whose declared shape requires `autoApproveOnMerge` while its PATCH schema makes it optional — gains a partial default so a task-pattern-only first PATCH stores the complete object. The registry's classification comment now states the true rule for every key: defaulted here, all-optional by declaration, or safe because the PATCH schema makes shape-violating partials unrepresentable (`ciCdSettings`).

Habitats that already hold legacy partial blobs (written before the v0.40.2 merge fix) are healed at the response choke point: habitat detail, list, and PATCH responses, `habitat.updated` SSE payloads, and manifest exports all serve complete default-filled shapes without a re-PATCH, mirroring what the per-service read resolvers have always done. Stored rows may stay partial; null blobs stay null.

## Route boundaries now have shape contracts

A new registry-driven suite drives the Fastify app end-to-end — GET detail, GET list, and PATCH bodies — against habitats seeded with legacy partial blobs and asserts every declared-required field is present. A regression to partial shapes at a route boundary now fails CI. The suite is mutation-proven: disabling the response normalization fails six of its seven tests.

## MCP instructions guide and all doc surfaces are guarded

The embedded agent skill guide had drifted: five stale short tool names (`orcy_mission`, `orcy_task`, `orcy_agent`, `orcy_message`, `orcy_subscription`) versus the live `orcy_habitat_*` names, an incomplete `orcy_habitat` action list, and a prose-only `orcy_admin` vocabulary. All are corrected. The docs-consistency guard — previously hardcoded to one tool in three files — now runs over every registry-driven dispatch tool across five doc surfaces plus the embedded guide, catching stale names, dead actions in table cells, inline calls, multi-line call blocks, and section prose. Doc cells that summarized actions as vague prose were rewritten to list the live action names. `orcy_admin` remains deliberately unadvertised in the tool list (its batch actions live under `orcy_habitat_task`); the guard's existence set encodes that policy so mentioning the tool is not flagged as drift.

## Releases no longer abort at the changelog step

The `after:bump` hook and the GitHub release-notes fallback in the release tooling spawned bare `pnpm`, which resolved an ambient package-manager shim instead of the pinned one and aborted releases after the version bump — the recurring failure that forced manual release fallbacks through v0.40.2. Both invocations now go through `corepack`. This release is the first to ride the fixed path. Lint is green on main again: the lone error-level diagnostic (a redundant spread in a test file) is removed.

## No operator action required

Behavior is strictly hardening and additive. Habitats holding partial settings blobs will simply start serving complete, default-filled shapes everywhere; agents following the corrected instructions guide will call tools that exist. No migration, no configuration. Operators with slow or redirecting webhook endpoints: watch for the next patch, which tightens webhook fetch behavior.
