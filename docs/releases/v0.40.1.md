# v0.40.1 — Patch: Retire the legacy finding PATCH endpoint

The v0.40.0 release restored the finding-triage lifecycle with command-style endpoints and left the legacy `PATCH /triage/findings/:id` adapter running as a compatibility window. This patch closes that window.

## Legacy PATCH retired

Every legacy `PATCH /triage/findings/:id` request — no-work, link-only, unlink, mixed, terminal, target-release, and unknown-field shapes alike — now returns a single typed `400 LEGACY_PATCH_RETIRED` response with zero writes, one deprecation log line, and no request-body parsing. Authentication still runs first: an unauthenticated caller gets `401` before the retirement response.

The retired adapter took its single-write primitive and request schema with it, along with the test-only service seams that mirrored the old behavior. Characterization suites moved to the lifecycle-command equivalents, and new retirement discriminators prove the zero-write guarantee per shape (spot-checked by breaking the fix and confirming the tests fail). The repository's writer inventory now lists only the lifecycle kernel, the cluster-admission participant, and the release kernel as production write authorities.

## Documentation corrections

The writer-inventory notes were corrected to match the code: the retained test fixture writer is called by 20 test sites across 14 suite files (not only release-activation suites), and `activateGroupWithClient` is described as writing activation state only — corrective mission links are written by the lifecycle kernel's `routeWithClient`. The API reference marks the PATCH endpoint as retired (mirroring the earlier `/promote` retirement), and the troubleshooting runbook documents the `LEGACY_PATCH_RETIRED` response with client-upgrade remediation.

## Operator Action Required

Legacy `PATCH /triage/findings/:id` is retired. Any client still issuing it must migrate to the lifecycle commands: `POST /triage/findings/:id/route`, `/activate`, `/resolve`, or `/wontfix`. There is no supported unlink via the API. Expect `400 LEGACY_PATCH_RETIRED` in logs from old clients; the stub performs zero writes, so no data remediation is needed.
