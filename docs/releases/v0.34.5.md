# v0.34.5 — Fix: mission code-evidence wire-name mapping

Companion to the v0.34.4 fix, closing the mission-level variant of the wire/backend name drift.

## Map `correct-mission-evidence-link` wire names to backend (`status`/`reason`)

The mission-level code-evidence correction action had the same wire/backend name drift as the task variant: the wire delivered `linkStatus`/`correctionReason`, but the backend `correctLinkSchema` requires `status`/`reason`, and the handler rest-spread the wire names straight through → 400. The handler now maps `linkStatus`→`status`, `correctionReason`→`reason` before calling the API.

The legacy unit test is now an honest wire→backend integration test (calls the handler with wire names, asserts the client receives backend names).

With this and v0.34.4, both the task and mission `correct-*-evidence-link` actions are fixed. The other code-evidence actions (`mark-not-applicable`, `report-gap`, `resolve-gap`) were verified **not** broken — a `buildReasonInput` helper already normalizes their prefixed wire names, and `resolve-gap`'s `resolutionReason` matches the backend schema exactly.
