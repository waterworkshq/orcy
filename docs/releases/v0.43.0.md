# v0.43.0 — Reliable Task Authority and Scoped Context

This release restores bounded webhook and notification delivery, binds agent execution to the exact Task claim, and makes review requirements and final approval proof durable. Task and shared-reader boundaries enforce their documented authority, remote streams expose minimal change notices, and newly written Workflows are constrained to their selected Mission. ADR-0052 records the ordinary Workflow projection and captured Failure Context policy.

Before this release, several advertised delivery and review paths were incomplete, execution sessions lacked consistent claim-bound fencing, and reader or child-object boundaries relied on authentication or earlier checks alone. The restored mechanisms retain recovery evidence and return explicit refusals when scope, ownership or finality no longer holds.

---

### Delivery and Recovery

Outgoing webhook retries resume eligible pending deliveries under a bounded reservation budget. Notification push has a different upgrade rule: only new notifications are pushed, while the legacy inbox remains readable without replaying its backlog. Required failure and release effects persist as fenced receipts with finite attempts and operator-visible exhaustion. These mechanisms do not promise exactly-once external delivery or persistence for every post-commit effect.

Daemon sessions are tied to the claimed Task's execution identity. Recovery, stale-agent cleanup, automation and plugin release paths use the contracted ownership checks and record their lifecycle effects. Agent deletion is atomic and reports blocking review references; uninstall does not erase recovery data after a known deletion refusal.

### Claims and Durable Review Safety

Agent start, submit, release and fail mutations on tokened Tasks require the execution token returned by the claim. Rejection preserves the owner's continuation token; starting rework mints the next execution epoch. Existing claims are not retroactively tokened by the migration.

Review requirements, winning claim-policy snapshots and generation-aware decisions are durable. Deleting a reviewer assignment does not erase its decision history or establish approval. Finalization requires canonical review proof; intermediate approvals can leave work submitted. Historical or ambiguous requirements are classified as `legacy_unknown` and require an independent eligible human resolution before attempting finalization. Resolving the requirement does not itself approve or complete the Task.

### Trusted Provider and Chat Decisions

GitHub and GitLab review webhooks bind a verified credential to exactly one Habitat and match immutable repository/project IDs against the configured allowlist. Merge auto-approval additionally requires the current opt-in, repository allowance, unique link, current Task ancestry, submitted state, a genuine known-zero review requirement and canonical finality. Release and CI/CD ingress remain separate contracts.

Signed chat traffic authenticates provider origin, not speaker authority. Review decisions require a configured provider workspace and explicit speaker mapping to an eligible local human. Existing integrations without that binding remain push-only.

### Scoped Reads, Evidence and Child Objects

The delivered Task routes derive access from the Task's actual Mission and Habitat. Team-Habitat human nonmembers, including global admins, are refused on these guarded ordinary routes. Final child/source predicates bind comments, subtasks, checklist items, effort, evidence and attachments to the contracted parent or typed source. Conditional writes report a real no-match instead of a false success; the attachment delete path commits database removal before filesystem cleanup and preserves its documented post-commit failure behavior.

Local evidence reports use fetched persisted identities, explicitly labelled legacy compatibility and a fenced storage bundle. Ambiguous repository/record identities and conflicting inputs are refused before writing. Existing records attach without refreshing their captured metadata. The accepted Mission-origin admission exception remains separate from distinct destination admission.

### Remote Grants and Stream Compatibility

The five basic shared Mission/Task/comment reads require an effectively active `read` grant in addition to target visibility and Habitat checks. General read and visibility grants may still be separate. Configured grant expiry is effective at the decision instant without waiting for a status sweep. Grace retains only the existing scoped heartbeat, submit and release continuation actions; it does not add target visibility or stream authority. Self/history surfaces outside those gates retain their separate contracts.

Remote SSE is now a change-hint channel: `remote.entity_changed` contains only `targetType` and the exact persisted `targetId`. Clients must perform a separately authorized shared query to fetch detail. Unknown event families and Task/Mission deletion do not produce notices; no tombstone or eventual-removal guarantee is implied. Local human/agent stream payloads remain unchanged. Remote read and visibility authority is refreshed at each event decision, with bounded idle revalidation; authorization is not transactional with the socket write.

### Workflow Context and Mission Integrity

Ordinary local/shared Task Workflow readers return every selected gate as `{gateType, satisfied, restricted: true}`. The shared Mission reader exposes only Workflow `status` and `version` plus restricted gates. Linked IDs, configuration, variables, provenance and timestamps are omitted. Selected counts, direction, type and state are deliberately disclosed, including satisfied and detached-workflow gates; this is restriction, not anonymity. These projections cannot determine Claimable: the claim mutation remains the authority.

Consistent-Habitat local Failure Context reads retain full diagnostics for admitted local readers, including Recovery agents querying a failed Task assigned to another agent. Individual Experience and opaque lifecycle metadata are an explicit diagnostic exception, not k-anonymous or source-complete disclosure. Captured/current Habitat mismatch is refused with `409 CONFLICT` as an integrity anomaly; no supported cross-Habitat Task transfer or automatic repair is introduced. Administrative and internal readers keep their separate full authority.

New Workflow attachment validates nodes and commits its Workflow/gates atomically. Template and Recovery publication check exact persisted Mission/Habitat and lineage at the final write statements on the caller's transaction client. Invalid scope or linkage rolls the published domain bundle back; earlier reservations or governance records may remain. Existing invalid rows are not scanned or rewritten, and triggers or later raw writers remain outside a permanent graph-integrity guarantee.

### What Stayed the Same

Local-agent Habitat access remains broad under the existing predicate; authenticated humans retain personal-Habitat access and team membership governs the guarded surfaces. Global administrative Workflow authority, general remote split grants and the Mission code-evidence origin exception are not replaced with new roles or assignment rules. Provider onboarding completion, historical replay entitlement and other documented residuals are not newly delivered by this release.

### Schema Changes

The production chain adds migrations `0076`–`0082`: webhook delivery leases; notification push epoch and destination-channel state; nullable Task/session execution tokens; durable effect receipts and provenance fields; release-event pointers; provider workspace/speaker mappings; and durable review requirements, snapshots, decisions and overrides.

The normal production runner applies these additive changes. Tokens and review decisions are not fabricated for historical work. Migration `0082` classifies provably never-claimed pending Tasks as uncaptured and uncertain historical Tasks as `legacy_unknown`. Use the migration index in `docs/DATABASE.md` for the precise storage and backfill contracts.

### Operator Action Required

Back up the database, uploads and required configuration before upgrade. Update the API, MCP/CLI clients and daemon together; custom agent clients must retain claim-pinned tokens and send them on tokened mutations rather than fetching a current token to bypass fencing.

Configure immutable GitHub repository and GitLab project IDs before relying on PR/MR linking or merge approval: empty allowlists now refuse that ingress. Review outgoing webhook subscriptions and pending backlog before startup because eligible pending deliveries become due. Legacy notification deliveries will not be pushed by the cutover.

Configure chat workspace anchors and speaker mappings where review commands are needed. Route `legacy_unknown` review requirements to an independent eligible human, not to assignee self-finalization. Provision active `read` scopes for the guarded shared queries, adapt remote-stream and ordinary Workflow consumers to the reduced response shapes, and investigate captured-Habitat mismatch instead of forcing disclosure or rewriting affiliation.
