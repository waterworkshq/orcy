# v0.41.1 — Patch: HTTP ingress verification hardening

Three hardening items on the HTTP ingress surface: stricter source scanning for Fastify acquisition, native strict Ed25519 verification for Discord interactions, and wire-format pinning for Slack slash commands. No route, authentication-policy, request, or response changes ship in this patch.

## Hardened source scanning for Fastify acquisition

The HTTP application is assembled in exactly one place, and a source-boundary guard keeps it that way by scanning for code that acquires the Fastify framework by package name. That scan previously matched the import specifier as written, so an acquisition written with JavaScript string escapes (`"\u0066astify"`, hex escapes, line continuations) could slip past it. The scan now resolves escapes first and matches on the resulting value, across static imports, dynamic `import()`, and `require()`. Near-miss package names that are legitimately allowed (`@fastify/*` scope, `fastify-raw-body`) remain allowed, and non-literal, data-dependent specifiers remain a documented residual of the scan.

## Native strict Discord Ed25519 verification

Discord interaction signatures are now verified with Node's built-in Ed25519 crypto instead of a third-party library, which is gone from the dependency graph (`tweetnacl` removed). Verification outcomes are unchanged for well-formed requests: a correct signature over the exact timestamp-plus-body bytes is accepted, while altered bodies, altered timestamps, and signatures made under a different key are rejected. Encodings that are not exactly 128 hex characters (signature) or 64 hex characters (public key) are now rejected outright instead of being decoded leniently. Malformed input fails closed — the verifier returns a rejection rather than throwing.

## Slack form-encoded wire format pinned under both prefixes

Slack slash commands arrive as `application/x-www-form-urlencoded` bodies. Regression tests pin, on the real wire format: a correctly signed form-encoded command completes under both the current (`/api/v1`) and the deprecated (`/api`) prefix; a `charset=utf-8` media-type parameter is accepted; percent-encoded and `+`-encoded values decode before the command handler runs; duplicate form fields resolve last-wins; and form-encoded traffic to any other route still fails content parsing under both prefixes, confirming the form parser stays confined to the Slack command scope. Of these proofs, the charset coverage and the deprecated-prefix extension of the other-route failure proof are what this patch adds; the rest was already pinned and is unchanged. No parser registration or signature behavior changed.
