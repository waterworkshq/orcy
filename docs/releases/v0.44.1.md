# v0.44.1 — Patch: Recovery and Triage Regression Coverage

v0.44.1 strengthens regression coverage for existing recovery, authorization, database-integrity, and triage UI contracts. It contains test and documentation changes only; production behavior is unchanged from v0.44.0.

## Database proof and current remote authority

New direct database tests reject release epoch/group pairs from different releases and proved automation checkpoints missing a receipt or proof timestamp. Matching valid rows and legal unproved states remain accepted. Remote-authority tests establish that persisted credential expiry and hard grant revocation invalidate a previously admitted snapshot, with live-authority controls. These tests protect the existing constraints and current-authority checks rather than introducing new permissions or schema rules.

## Recovery, contention, and legacy repair

Recovery tests exercise partially proved deliveries while cooldown and hourly admission limits are genuinely tripped, preserving the distinction between resumed work and fresh admissions. A real file-backed SQLite lock verifies that writer acquisition attempts `BEGIN IMMEDIATE` once and does not enter the command after acquisition fails. Legacy repair coverage checks identical-input replay and changed-input refusal for older ledger rows without a recorded before-state digest, including unchanged finding state after refusal.

## Triage request and form contracts

UI tests pin route and activation request paths, HTTP methods, and positive payload values. Deferred-backlog coverage distinguishes an activated release-deferred finding from a still-triaged row, and finding-change coverage verifies that edited descriptions and release-gate versions do not leak into the next finding's submitted command. Existing fixtures are reused; no production hooks, dependencies, time-limit increases, or new test framework are introduced.

## Verification

The additions passed focused API and UI suites, both package compilers, and scoped lint with zero errors and four existing warnings. Bounded test-owned fault checks demonstrated the intended assertion failures; exact test files were restored and passing checks repeated afterward. Main CI passed on both coverage commits, including production migration/startup and the package-manager boundary guard. The preceding v0.44.0 preflight passed all seven package builds/typechecks and 11,870 tests with two existing skips; that historical result is not presented as another full-suite run for this patch. Release-day focused checks and the managed release's pre-push guards are verified separately.

## No operator action required

No production code, schema, migrations, API contracts, configuration variables, or dependency versions change. Existing v0.44.0 upgrade guidance still applies. This release does not require new role assignments or database maintenance beyond that guidance.
