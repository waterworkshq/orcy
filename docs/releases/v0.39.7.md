# v0.39.7 — Patch: Structured automation rule draft recommendations from extraction

Rule recommendations emitted by the extraction Learning Loop were prose-only — no machine-readable trigger, condition, or action payload. Operators had to manually translate the recommendation text into an automation rule. This patch upgrades the recommendation pipeline to emit validated `AutomationRuleDraft` payloads and render draft previews in the finding detail view.

## What changed

- **Extractor** (`extractionExtractors.ts`): the `detectRuleRecommendations` pattern detector now constructs a structured `AutomationRuleDraft` — with a trigger, condition, actions, cooldown, and rate limit — instead of emitting `structuredPayload: null`. The draft is disabled by default (`enabled: false`) and flagged with `requires_human_review` and `recommendation_draft` caveats.

- **Validator** (`extractionValidator.ts`): the finding-type payload validator previously rejected any non-null `structuredPayload` on `rule_recommendation` findings. It now accepts either `null` (prose-only) or a payload validated against `automationRuleDraftSchema` (introduced in v0.39.6), rejecting only invalid drafts.

- **Finding detail UI** (`ExtractionFindingDetail.tsx`): when a structured payload is present, the finding detail renders a draft preview card showing the rule name and a description. Prose-only recommendations continue to render the existing notice.

## Verification

- `@orcy/api` typecheck: clean.
- `@orcy/api` tests: 23 passed across `extractionExtractors.test.ts` and `extractionValidator.test.ts`.
- `@orcy/ui` typecheck: clean.

## No operator action required

No schema changes, no migrations. Recommendations remain disabled by default; operator review is required before any draft becomes an active rule.
