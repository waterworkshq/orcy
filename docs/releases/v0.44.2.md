# v0.44.2 — Patch: Governance Read and Review Validation

v0.44.2 hardens role-definition reads and MCP reviewer assignment, clarifies unknown custody audit attribution, and improves governance race-test diagnostics.

## Role-definition reads reject malformed stored permissions

Role-definition detail reads now validate stored permission JSON and require a nonempty string array. Damaged stored revisions return a controlled 400 `VALIDATION_ERROR` instead of an unclassified parse failure or an invalid response shape. Custom-namespace authorization runs before parsing, so forbidden callers retain 403 `AUTHORIZATION_DENIED` responses without receiving revision content. Reads do not repair or rewrite stored history.

## MCP reviewer types are checked before the HTTP call

The MCP review tool now advertises and accepts only `human` or `agent` for `reviewerType`. Omitting the field still defaults to `human`; invalid supplied values are rejected before a client request. Both MCP skill documents also explain that an optional roster expectation must be the 64-character lowercase-hex `reviewersToken` returned by a prior `list_reviewers` response for the same Task.

## Unknown custody attribution has explicit consumer semantics

The retained `actor_type='human', actor_id='unknown'` pair is documented as unknown attribution, not an identified human or system principal. Audit consumers receive canonical SQL projection and count filters so these rows are excluded from identified human activity counts. Authenticated served commands retain their real actor identities; no history is inferred or backfilled.

## Maintenance and test diagnostics

Governance race tests now report worker exit codes, signals, process errors, and bounded stderr while waiting for filesystem markers, and verify that owned children are reaped. An unused import custody helper and its otherwise-unused traversal are removed; active restore-aware publication behavior is preserved. Repository ignore rules now cover local dot directories at any depth while retaining already tracked configuration.

## Verification

All seven workspace package builds and typechecks passed. The full workspace test run passed 11,901 tests across 805 files, with two existing skips; this includes 8,786 API tests and 782 MCP tests. Full-workspace lint reported zero errors and 376 warnings. Real worker code/signal failures and owned-child cleanup are covered, and bounded mutation probes established that the role-read assertions reject leaked null and empty-array fixtures on both authorized and forbidden paths.

## Operator Action Required

No server configuration change, schema migration, dependency update, or role reassignment is required. Existing valid role reads and reviewer assignments keep their behavior. Audit consumers that report identified human activity should apply the documented unknown-attribution filter.
