# v0.34.2 — Fix: review-dispatch required-args drift

A single correctness fix in the MCP dispatch validation layer.

## Replace review-dispatch private `requireArgs` with the canonical `requiredFor` map

`review-dispatch.ts` had a private `requireArgs` helper that diverged from the canonical validation path in two ways: it **threw** (instead of returning an `isError` ToolResult like `createDispatchHandler`), and `!args[key]` rejected `0`/`false` (drift from `validateRequired`'s `undefined`/`null`/`""` rule). Deleted the helper; `review-dispatch` now uses a `REVIEW_REQUIRED_PARAMS` map passed to `createDispatchHandler`, matching the pattern already used by `task-dispatch`.
