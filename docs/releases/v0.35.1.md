# v0.35.1 — Patch: Three Deferred Item Cleanups

Three small, scoped cleanups — no behavior change for any non-remote actor type, no schema change, no API contract change.

## Fix 1 — `resolveActorName` falls through to `displayName` for remote actors

The board summary timeline rendered remote actor events with the raw `actorId` (a UUID-shaped string) because `resolveActorName` only branched on `"system"` and `"human"`; everything else fell through to `agentNameMap.get(actorId) ?? actorId`, which is empty for remote actors.

Added a batch-built `remoteParticipantNameMap` (sibling to the existing `agentNameMap` pattern, populated via `getRemoteParticipantsByHabitat(habitatId)`) and a new branch in `resolveActorName` that looks up `displayName` for `remote_human` and `remote_orcy` actor types. Falls through to the raw `actorId` only when the participant row is missing. No behavior change for non-remote types.

## Fix 2 — `codeEvidenceCollector` widens `actorType` cast to `ActorType`

The `codeEvidenceGapRow` projector cast `actorType` to a 3-value union (`"human" | "agent" | "system"`) but the underlying `reportedByType` column is the full 6-value `ActorType` union (`"human" | "agent" | "system" | "remote_human" | "remote_orcy" | "remote_pod"`). The over-narrow cast hid the widened type from `normalizeAuditActorAndSource`'s type checker.

Widened to `actorType as ActorType` so the cast is honest. Runtime behavior unchanged — `AuditActorRef.type` continues to receive the original string verbatim.

## Fix 3 — `compiledStartup` smoke test pins pnpm version

The compiled-binary smoke test used bare `pnpm --filter @orcy/api build` in `execSync`. Shells whose ambient `pnpm` is v11 (not the project's corepack-pinned 9.0.0) caused the build to fail; `corepack pnpm@9.0.0` worked in the shell but not in `execSync`'s subprocess due to fnm PATH propagation.

Changed the invocation to `npx pnpm@9.0.0 --filter @orcy/api build`. `npx` resolves the version-pinned package from `node_modules` (or fetches it on demand) regardless of ambient PATH, so fnm PATH propagation and ambient v11 no longer affect the subprocess. CI was already protected via explicit `corepack prepare pnpm@9.0.0 --activate`; this change makes local environments match.
