# v0.34.1 — Fix: MCP Dispatch Validation Bugs

Two standalone correctness fixes in the MCP dispatch layer, independent of the action-catalog deepening (Candidate 7).

## Bug 1 — Dead `requiredFor` field on `DispatchToolConfig`

`DispatchToolConfig.requiredFor` was declared on the interface but never read by `createDispatchTool`. The live validation path is `createDispatchHandler`'s separate `requiredFor` parameter → `validateRequired`. Only the triage dispatch module populated the dead field, creating a misleading duplicate of the live validation map. Removed the field from the interface and deleted triage's dead declaration.

## Bug 2 — `set_focus_mission` validation blocked the "clear focus" path

The triage dispatch handler's live `requiredFor` map required `missionId` for `set_focus_mission`, but the handler (`triageSetFocusMission`) explicitly supports `missionId: null` or omission to clear the habitat focus. An agent calling `set_focus_mission` without `missionId` was rejected by `validateRequired` before the handler ran — the "clear focus" capability was unreachable through MCP. Fixed by removing `missionId` from the required list.
