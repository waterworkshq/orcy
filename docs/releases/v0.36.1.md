# v0.36.1 — Patch: Settings merge + SSE helper extraction

Two deferred code-style items from the v0.36.0 review (CS-20 + CS-21).

## CS-20 — Strip field-level `.default()` from PATCH sub-schemas (data-loss prevention)

`anomalySettingsSchema` and `autoAssignSettingsSchema` had field-level `.default()` on every sub-field (e.g., `enabled: z.boolean().optional().default(true)`). Zod injects these defaults at parse time, before `habitatService.updateHabitat`'s deep-merge runs. A partial PATCH like `{anomalySettings: {enabled: false}}` would get Zod-parsed to `{enabled: false, scanIntervalMinutes: 5, ...}` (defaults filled in), then the shallow merge would overwrite existing custom values with Zod-injected defaults.

Fix: removed all field-level `.default()` from both schemas. Omitted fields now stay `undefined`, the deep-merge skips them, and existing stored values are preserved. The `DEFAULT_*` constants remain for initial habitat creation. Also removed `.default(false)` from `codeReviewSettingsSchema.autoApproveOnMerge` — same pattern.

Pre-existing since v0.23.3/v0.18; surfaced by v0.36.0's `z.infer` consolidation.

## CS-21 — Extract `publishHabitatUpdate` helper (SSE consistency)

`maskSecretSettings` + `rebuildHabitatSecretCache` + `sseBroadcaster.publish` was hand-inlined in three places (`habitatService.updateHabitat`, `prioritization.ts` route, `wikiSchedulerService` two sites). The three copies were already drifting — only the service path called `rebuildHabitatSecretCache()`.

Fix: extracted `publishHabitatUpdate(habitatId, habitat)` into `habitatService.ts` as the single owner of mask + cache rebuild + SSE broadcast. All three call sites now route through it. The cache rebuild on the prioritization/wiki paths is a cheap no-op (those fields aren't in the secret cache), but the unified contract ensures future masking or cache changes propagate automatically.
