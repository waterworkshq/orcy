# v0.41.4 — Patch: Pinned-pnpm integrity across builds and installers

Build-and-install tooling hardening surfaced by the v0.41.x patch train: every path that spawns pnpm now runs the version the repository pins, and the pin itself is bumped to the latest 9.x release.

## Every root script runs the pinned pnpm

The repository declares its package manager in the standard `packageManager` field, but most root scripts invoked a bare `pnpm`, which resolves whatever pnpm happens to be on PATH. Under a Corepack parent that mismatch fails outright (the pinned 9.x refuses to self-switch to an ambient 11.x), breaking the canonical `corepack pnpm build` entry point. All seventeen root scripts now enter through `corepack pnpm`, so the canonical build, typecheck, and test commands work from any environment regardless of its ambient pnpm.

## Installers no longer install or mutate a global pnpm

Both installers previously ran whatever `pnpm` was on PATH — and when none was found, `install.sh` installed an unversioned `pnpm` globally via npm, mutating the user's toolchain with whichever version was latest that day. Both `install.sh` and the TypeScript installer now derive the exact pnpm version from the `packageManager` field of the source tree they are installing, run it through Corepack (bundled with Node.js), and fall back to an ephemeral `npx pnpm@<version>` invocation when Corepack is unavailable. Nothing is installed globally, the user's environment is never modified, and a source tree whose pin is missing or malformed fails with a clear error instead of building with an arbitrary version. A structural test now blocks any future bare-`pnpm` root script from reaching main: it runs in the local pre-push gate and in CI.

## pnpm updated to 9.15.9

The package-manager pin moves from 9.0.0 to 9.15.9 (the final 9.x release). This is the first bump through the new deliberate-bump workflow: the version is declared in exactly one field, the installers and CI derive it automatically, and the lockfile is unchanged within the 9.x series — so installs and builds behave identically, just on the current patch release of the toolchain. End users installing this release receive 9.15.9 automatically through the Corepack/npx mechanism above.

## Verification

- Full monorepo test suite: 9,779 passed, 2 pre-existing skips, 0 failures — identical totals before and after the pin bump.
- Serial canonical gates under pnpm 9.15.9: `corepack pnpm build`, `corepack pnpm typecheck`, and `corepack pnpm test` all pass; direct `pnpm build`/`pnpm typecheck` compatibility confirmed.
- `pnpm-lock.yaml` is byte-identical across the pin bump; no dependency changes ship in this release.
- Installer suite: 151 tests covering runner selection (Corepack-preferred, npx fallback, fail-closed), command propagation through the archive, local, and runtime-dependency paths, and the hermetic `install.sh` bootstrap contract (POSIX-clean under dash).
- Three independent fresh-context reviews accepted the installer, bootstrap, verification, and pin-bump changesets, including read-only mutation replays.

## No operator action required

No schema changes, no migrations, no API changes, no configuration changes. Existing installs keep working; new installs simply stop depending on (or modifying) a global pnpm.
