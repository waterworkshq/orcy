# v0.41.3 — Patch: Repository null contracts and test reliability

Three hygiene items: nullable repository reads now honor their documented null contract, a test-only composition helper is gone from production source, and two timing-flaky or residue-prone test suites are made deterministic. No route, authentication-policy, response, schema, migration, dependency, or production outbound behavior changes ship in this patch.

## Nullable repository reads return null

Twelve repository reads documented as returning `null` when no row matches actually returned runtime `undefined` — the type-level claim and the runtime value disagreed. Each site now binds the row and normalizes honestly, so an absent external intake candidate, external issue link, habitat health snapshot, integration connection, integration sync run, mission, review rule, active sprint, or task reviewer reads back as literal `null`. Ten of the sites are direct public reads; one is the mission-by-id lookup, whose public null-on-absence behavior was already correct and is now locked by a test covering both id spellings; the last is an internal just-inserted read that still throws its not-found error if its own insert cannot be read back. This is the only runtime-behavior change in the patch, and it is invisible on the wire: every caller treats these results as present-or-falsy, and absent rows are serialized at the route boundary exactly as before. A new repository-level test suite pins all eleven public reads to strict null-on-absence.

## Test-only GitHub webhook helper removed from production

The GitHub issue webhook service exported a combined resolve-and-dispatch helper that nothing in production called — the verified-ingress guard resolves credential authority once from the request's HMAC signature over the exact raw bytes, the route reads that resolution and dispatches per matched connection, and the export existed only so the service's own test file could call the pairing as one unit. The export is deleted; the test file composes the same two production seams locally, so its coverage — real HMAC signing, real database lookups, per-connection fault containment — is unchanged. The production route, the ingress guard, dispatch behavior, and fail-soft 200 acknowledgments are byte-identical, and the architecture document's webhook-flow description now names the live path instead of the removed helper.

## Deterministic SSRF and staged-migration test proofs

The localhost SSRF rejection test previously proved the network transport was never reached by asserting the call took exactly zero milliseconds — true in practice, flaky under a loaded scheduler. It now stubs the transport directly and asserts it was never called, before asserting the rejection result; the exact-zero timing assertion is gone with no replacement time bound. The outbound URL validator itself is unchanged, and `latencyMs` remains part of the webhook test-result shape.

The staged production-migration suite now cleans up after itself: per-database cleanup also removes SQLite `-journal` sidecar files, and the suite removes its exact owned temp directory at start and at close, so a hard-aborted run no longer leaves residue behind. Two consecutive runs leave no directory and no working-tree change, and a run that starts with planted residue removes it at suite start before any test executes.

## Verification

- Full API suite: 6793 passed, 2 skipped (pre-existing), 0 failed, across 420 files.
- API typecheck, monorepo build of all packages (via the project-pinned package manager), and lint: clean (0 lint errors).
- Null contracts: the new repository test suite fails ten of its eleven cases against the pre-change code and passes all eleven after it; both mission id spellings are covered, and the mission creation path's throw-on-unreadable-insert is preserved.
- Mutation coverage: each load-bearing check verified in this patch was bypassed one at a time and the intended tests failed while neighbors stayed green. Temporarily allowing localhost past the outbound URL validator turns exactly the three localhost-blocking tests red — including the transport-never-reached proof, which fails with the stubbed transport actually invoked once — while the other sixty-one outbound tests stay green. Disabling the staged-migration suite's startup cleanup while planting stale files in its temp directory fails a residue probe at test time; restoring the cleanup removes planted residue at suite start with all nineteen tests green.

## No operator action required

No schema, migration, configuration, dependency, or API contract changes. The null-return normalization changes no HTTP response: absent rows were already serialized as null at the route boundary. Nothing to do on upgrade.
