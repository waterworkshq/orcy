# v0.46.1 — Maintenance: changelog dedupe, zero-warning lint, CI typecheck, a stable concurrency proof, pnpm 10

Five maintenance changes closing the post-v0.46.0 backlog. No schema migrations, no served-contract changes, no runtime behavior changes in the api/ui surfaces.

## Changelog dedupe — the trimmer now removes merge-era bullets

The release trimmer (`scripts/trim-changelog.mjs`) caps the changelog at three release sections; it now also removes repeated identical bullets within a section (merge-commit landings emitted the same body paragraph once per landing — one such bullet lived in thirteen copies) and drops the generator's empty-body placeholder bullets. The committed changelog is cleaned once in the same change, and the trimmer has node:test coverage under `pnpm test:scripts`.

## Lint backlog triaged — 402 warnings to zero

The workspace lint backlog is gone: dead imports and unused bindings removed, shadowing bindings renamed, in-place reverses switched to `toReversed()`, caught errors given causes, and five pure helpers hoisted. The intentional patterns moved into config with rationale: the underscore-prefix convention and in-place-sort idiom are off globally, and test/fixture locality keeps three rules off for test code. Two files carry scoped `no-shadow` overrides where the flagged bindings are module-level siblings or a kernel-signature convention, so no semantic shadow exists. `pnpm lint` now reports **0 warnings, 0 errors**, and the CI lint job carries real signal.

## CI now typechecks every package

The `lint-and-tests` workflow gained a Typecheck (all packages) job: after building `@orcy/shared` and `@orcy/daemon` (whose built `dist/` the cli package's typecheck resolves through the workspace symlink — absent on a fresh checkout), it runs every workspace package's `typecheck` script. Type errors now fail a pull request in about thirty seconds instead of surfacing deep inside the production-migration gate. CONTRIBUTING also documents that `.github/` is gitignored and workflow files are force-added.

## The rerun concurrency proof runs in its own serial pass

The Learning Loop multi-process fresh-rerun proof (forked workers over a cold file database that boots the full migration chain) intermittently exceeded the default five-second test timeout under the full suite's file parallelism. It now runs as `pnpm test:extraction-concurrency` with `--fileParallelism=false` — the same isolation pattern the perf suite already uses — and the CI test job runs it as its own step after the main suite, so the proof stays machine-gated without sharing the parallel pool. The invariant it proves is unchanged.

## pnpm 10.34.8

The package-manager pin moves from 9.15.9 to the newest 10.x. pnpm 10 blocks dependency lifecycle scripts by default, so `pnpm-workspace.yaml` allowlists exactly one: better-sqlite3's install script (the native production driver binding). The lockfile is unchanged, and the full canonical gate set passed under the new pin — including the production-migration suite on the real better-sqlite3 driver and the CI workflows, which derive the pin from `packageManager` and ran green under it on main.
