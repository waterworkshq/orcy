# v0.36.0 — Deepen: Public Habitat Transport

Architecture-deepening release that establishes `PublicHabitat` as the single transport contract across server, UI, and MCP. Consolidates the server's three divergent update-input shapes into one `z.infer`-derived type, fixes two stale-UI SSE bugs, aligns MCP types to masked shapes, and removes dead tooling. Architecture review candidate 9 from the 2026-07-11 review.

## Server update-input consolidation

The Zod schema (`updateHabitatSchema`) is now the single source of truth for what a habitat PATCH accepts. The service function's input type is derived via `z.infer`, eliminating the `as` cast that previously hid a type-system lie where Zod validated 11 fields but the service type only accepted 7. The repo keeps its broader 16-field type (intentional — 6 internal callers bypass the service).

All settings blobs (`retrySettings`, `anomalySettings`, `autoAssignSettings`, `triageSettings`, `releaseSettings`, `roadmapSettings`, `codeReviewSettings`, `ciCdSettings`) are now deep-merged with existing stored values in the service, so a partial PATCH only overwrites the fields the caller explicitly provided.

## SSE broadcast fixes (2 stale-UI bugs)

Two routes bypassed the service and called the repo directly, skipping the `habitat.updated` SSE broadcast:

- `PATCH /habitats/:id/roadmap-focus` now routes through `habitatService.updateHabitat` — SSE fires automatically.
- `PUT /habitats/:id/rules` (prioritization) and `wikiSchedulerService` now add explicit `sseBroadcaster.publish` after direct repo updates.

Both bugs caused the UI to require a manual refresh after focus-goal or prioritization-rule changes.

## MCP type alignment

MCP switched from raw `Habitat` (secret-bearing persistence type) to `PublicHabitat` (masked) in all return types. The 6-field `HabitatSettings` type-lie (which never matched the ~20-field runtime shape) was deleted. Legacy `boardId` parameters renamed to `habitatId` across `HabitatClient` and the `orcy_habitat` dispatch tool.

The dead `updateHabitatSettings` MCP tool was removed — it 401-ed on every call because the PATCH route uses `humanAuth` and MCP authenticates via `agentAuth`. No agent workflow broke. Scoped sub-routes (`/roadmap-focus`) remain the pattern for future agent write needs.

## Breaking changes

- **MCP wire format:** `boardId` → `habitatId` in `orcy_habitat` dispatch tool params and predictions/bottlenecks return properties.
- **MCP tool surface:** `update-settings` action removed from `orcy_habitat` dispatch tool (was dead code — 401 on every call).
